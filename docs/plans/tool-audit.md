# Tool audit (2026-10-11)

Question: does every tool have a clear purpose, which are redundant, and where do context, time and retries go?
Method: the tool list and schemas of the built server, the tools' documentation and tests, and the calls an agent actually made, read from the local Claude Code transcripts of the Chaos Redux sessions (16 tool kinds, 304 calls, with their result sizes and errors).
The sample is small and ends before the 4.0.0 argument shorthands, so it shows where the cost was, not the present error rate.

## Do the probability tools help?

Yes, for one workflow, and the two that remain are enough.
A weighted surface (an `ai_will_do`, an MTTH, a `random_list`, an `ai_chance`) cannot be judged by reading: the weight depends on modifiers that read the state, and a change moves the odds of other choices.
`probability_inspect` answers "what are the weights and probabilities in these scenarios, and which facts are missing", which an author otherwise computes by hand; `probability_analyze` answers "what changes if I edit this" (compare), "where does it flip" (sweep), "how likely over time" (simulate and sequence) and draws it.
The Chaos Redux instructions require a before-and-after comparison for every changed weight, so the workflow exists; the transcripts show 12 calls, mostly in audits, because few sessions edit weights.
Six tools were too many for that (each repeated the same candidate and scenario inputs); two keep the inputs in one place.
The tools stay honest about limits: a result states which facts were assumed, and an unmodelled trigger leaves the weight unresolved instead of guessed.

## Changes made in this audit

- Result size: 8 resource links beside the summary, images and reports first (`MAX_CONTENT_RESOURCE_LINKS`), every artifact still in `structuredContent.artifacts`; passed validation checks that only say "not detected" are not listed.
- Actionable errors: the known-mistake rules give the fix for seven documented mistakes (`script_validate`, `reference_context`, `error_log`); the repeated-argument failures were already replaced by `INVALID_ARGUMENTS` with a working call.
- Retry loops: no tool retries internally; a call that fails on a stale revision (`REFERENCE_REVISION_STALE`, `TRANSACTION_STALE`) says to search or inspect again, and [Troubleshooting](../troubleshooting.md) lists each code with its action.
- Timeouts: unchanged. Long work runs as a negotiated task or background job with a deadline (`jobDeadlineSeconds`), and the warm worker removes the cold index from the second job on.

Not changed, with the reason: the four heavy analysis tools (`impact_inspect`, `mechanic_test`, `package_check`, `scenario_test`) have no sampled use, but the Chaos Redux integration guide names them, and each has a distinct input and a test suite; removing them would cost the Chaos Redux regression workflow more than the 7 KB of `tools/list` they add.
