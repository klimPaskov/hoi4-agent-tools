# Repository comparison for local HOI4 references

Five repositories were reviewed at the pinned commits below. They provide examples for narrow source lookup, documentation search, and map validation. They are design references, not dependencies or permission to copy third-party source into this server.

| Repository                                                                                                     | Useful example                                                                      | Application here                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [paradox-script-mcp](https://github.com/106-/paradox-script-mcp/tree/e6aff2c35d29d89ec1810ff8f6490d84a2c66ced) | `list_symbols`, line lookup, and nested structure reads avoid whole-file responses. | Use the existing lossless parser and `SymbolIndex` for bounded source lookup. Its reviewed snapshot declared no license and warns that some syntax is unsupported. |
| [clausewitz-mcp](https://github.com/jacklenzotti/clausewitz-mcp/tree/11724f3608f58c63d7882f075645cb5c19050680) | Exact lookup of generated trigger, effect, scope, and modifier documentation.       | Prefer installed game documentation; allow a user-provided, versioned `script_docs` source without launching the game.                                             |
| [RHoiScribe](https://github.com/czxieddan/RHoiScribe/tree/b2a1473975d924e7d1648959bcc03e5c244c30b7)            | On-demand guidance, source-linked diagnostics, and scope inspection.                | Keep retrieval narrow and diagnostics tied to source. Its AGPL-3.0 implementation and game-launch route are outside this product.                                  |
| [HOI4-MCP](https://github.com/cpntodd/HOI4-MCP/tree/e7101f6bee5b6536c965e05935659af4a7220cc5)                  | Local vanilla index, ID checks, and project rules.                                  | Extend the shared index and return cited rules; avoid a second database, GPL-3.0 code, fuzzy edits, logs, and game launch.                                         |
| [HOI4-Map-Editor](https://github.com/AdriianCOE/HOI4-Map-Editor/tree/8531064bde12bd84425e714804916f36bf1ff669) | Candidate validation, dated history preservation, and interrupted-save recovery.    | Check those cases in the existing map inspect/render/rewrite path. Confirm the fork's full license and notices before any code reuse.                              |

The five projects' READMEs and feature guides were reviewed on 2026-09-26. None of the four knowledge-layer projects supplied a dedicated cited search over a user's offline Paradox Wiki snapshot. This server's local reference tools address that gap: `hoi4.reference_context` selects relevant sections, `hoi4.reference_search` finds them, `hoi4.reference_read` opens bounded spans, and `hoi4.source_lookup` finds exact source precedents. Installed documentation is the primary syntax authority; an optional offline wiki adds broader guidance. [ADR 0036](../adr/0036-local-reference-retrieval.md) records the architecture, and the [reference benchmark](../research/reference-benchmark.md) records measured retrieval behavior.

For example, a GUI task can ask `reference_context` for scripted GUI material, read the returned installed-game and wiki sections, then use `source_lookup` to inspect one vanilla control definition. The domain inspector and renderer still provide layout evidence; reference retrieval does not establish in-game behavior. Citations should retain path, line span, and revision, and missing or omitted sources remain explicit.

The map editor comparison leaves useful checks for map changes: preserve dated state-history blocks, validate the combined candidate before atomic replacement, reject stale source, verify recovery from later-file failure, and inspect/render the affected area after a rewrite. Sparse province IDs remain a load-sensitivity question: read-only inspection should report exact gaps, while a rewrite should retain its gap error until stronger engine evidence supports another rule. Unusual bitmap dimensions, incomplete region coverage, coastal flags, and missing definition colors also need explicit evidence. These are review cases, not claims that every operation has been engine-verified.

The reference service ships code and schemas without copied wiki pages, installed-game documentation, mod source, or game artwork. It reads only configured, authorized local roots. Future retrieval work should measure section recall, citation correctness, response size, latency, and follow-up reads on real GUI, focus, event, technology, and decision questions before widening the response surface. The [research notes](../research/references_and_open_questions.md) retain open source questions and the [source ledger](../research/source-ledger.md) retains provenance.

## Source-level review and implementation

The five default-branch commits were checked again on 2026-10-03 and still matched the pinned revisions above.
The review included `src/paradox_script_mcp/tools/structure.py`, `clausewitz_mcp/validate.py`, RHoiScribe's CWT feature guide, HOI4-MCP's learned-rule representation, and the map editor's sparse-ID design and tests description.
No implementation code from these projects was imported.

| Idea                           | Decision and evidence                                                                                                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nested source exploration      | Implemented through exact keyed and entry-index navigation, duplicate-key selection, structural pagination, and source-boundary tests. Unlike an unbounded deep expansion, each page retains its budget and continuation. |
| Native documentation grounding | Implemented through authority-filtered search/read and standalone syntax, command-kind and scope checks, with unknown helpers and parameters explicitly unresolved.                                                       |
| Warm process state             | Applied to the shared scanner and authenticated analysis cache: resident facts avoid redundant hydration, persistence is bounded, and file I/O overlaps within source/handle ceilings.                                    |
| Learned-rule memory            | Implemented as a reviewed rule file with detectors and no mutable database; see the mistake-capture review below. Corrections require source evidence and human-readable repository changes.                              |
| Map save safety                | Existing atomic candidate validation, dated-history protection, connected edits and recovery remain the foundation. Sparse-ID editor round trips do not establish game loading behavior.                                  |

Richer CWT parameter/type validation and line-to-owner symbol discovery remain useful future candidates.
They require separate compatibility and performance work rather than being implied by the native-command checker.
The current tool contract, tests and measured limits are documented in [ADR 0039](../adr/0039-source-navigation-and-native-command-checks.md), [the reference guide](../reference.md), and [the benchmark](../research/reference-benchmark.md).

## Live-testing and mistake-capture review (2026-10-11)

Two more projects were reviewed from their repository pages, source listings and the named files: [smerss/Clausewitz-MCP](https://github.com/smerss/Clausewitz-MCP) (MIT, Python; plays the Linux build by reading process memory and posting commands to the game's command queue) and a second pass over [cpntodd/HOI4-MCP](https://github.com/cpntodd/HOI4-MCP) (GPL-3.0, Python), concentrating on `learning/db.py`, `detector.py`, `seeder.py` and the `record_mistake`, `resolve_mistake`, `get_learned_rules`, `export_learned_rules`, `import_learned_rules` and `session_review` tools.
Nothing was copied from either; every row below is a reimplementation of an idea.

### cpntodd/HOI4-MCP: mistake capture and resolution

| Idea                                                                                            | Decision                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A rule store that agents write with `record_mistake` and retire with `resolve_mistake`          | Adopted as a reviewed, versioned file instead of a mutable database: `src/hoi4_agent_tools/reference/known-mistakes.json` ships with the server, is validated when the server loads, and changes only through a reviewed commit. A rule that no longer applies gets `status: resolved` and a required resolution (date and reason); it stays in the file as history and is not applied. |
| Rules carry a pattern, a correction and a severity                                              | Adopted, and each rule must also cite its source (wiki page, heading and item, or a game documentation file). Every active rule has a detector that works on the parsed script, so the rule flags the mistake in a checked file and names the fix; a test fails if a rule has no detector or a detector has no rule.                                                                    |
| `get_learned_rules` before a task                                                               | `hoi4.reference_context` returns the `knownMistakes` of the requested surface (id, title, fix), so the lookup needs no extra tool.                                                                                                                                                                                                                                                      |
| Application while editing                                                                       | `hoi4.script_validate` in file mode runs the detectors (`known_mistakes` in `checksPerformed`) and reports each hit as `KNOWN_MISTAKE_<ID>` with the symptom and the fix.                                                                                                                                                                                                               |
| `detector.py`: group `error.log` messages by a normalised signature and propose candidate rules | `hoi4.error_log` already groups by shape (`patterns`) and compares launches. It now names the known mistake and its fix when a logged message matches a rule's `logPattern`. Turning a recurring unknown pattern into a rule stays a human step with a citation (see the development guide).                                                                                            |
| Token-overlap deduplication, `session_review`, JSONL export and import                          | Not adopted. A closed, reviewed list has unique ids enforced by a test, and sharing is the repository itself.                                                                                                                                                                                                                                                                           |
| 14 seed rules                                                                                   | Each was checked against the offline wiki and the game documentation. The ones the sources do not state (`log` lines in focus rewards, `search_filters`, GUI state design) are style opinions or belong to workflow skills and were not adopted. The wiki's own "Common mistakes" lists supplied the seven rules that are shipped.                                                      |
| GPL-3.0 licence                                                                                 | No code or rule text copied; the rule wording is original and cites the wiki.                                                                                                                                                                                                                                                                                                           |

The shipped rules are `event_triggered_only_with_mtth`, `event_fires_every_day`, `news_event_not_major`, `event_date_window_too_tight`, `event_namespace_missing`, `event_numeric_id_invalid` and `temp_variable_scope_prefix`.

### smerss/Clausewitz-MCP: live testing and game interaction

The project drives Linux Hearts of Iron IV through recovered binary layouts, so its transport does not apply to this Windows, interface-driven server.
Its safety lessons do, and they are tracked in the HOI4 Live Tools repository (`docs/reference-review.md` there) because that server owns game interaction.

| Idea                                                                           | Decision                                                                                                                              |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Verify legality and read back the effect of every command                      | Already a rule of HOI4 Live Tools: each action re-reads the screen or state and reports what changed.                                 |
| Idempotent toggles (pause is a toggle, so send it only when the state differs) | Already so for time control and for plan execute and hold.                                                                            |
| Waits that always return by a day limit                                        | `hoi4_advance` is bounded by `days` and stops on decision points.                                                                     |
| Refuse to act when the played country cannot be resolved                       | Already so for the campaign tools (stale telemetry is ignored).                                                                       |
| Gate irreversible actions behind an explicit confirmation                      | Already so for declaring war and shutting the game down; the console and cheats are refused in campaign mode.                         |
| A `doctor` command that locates the install                                    | `python -m hoi4_live selftest` is the equivalent offline check.                                                                       |
| Short, readable diagnosis of the game's own error messages                     | Added: `hoi4_logs` attaches the documented fix to the four event messages above.                                                      |
| Do not re-issue a movement order every tick; ironman and multiplayer detection | Recorded as precise follow-ups in the Live Tools review; both need live verification that cannot be done while campaigns are running. |
| Process-memory reads, command-queue posting, attack and encirclement planning  | Not applicable: Linux-only, patch-fragile, and superhuman play is a stated non-goal.                                                  |
