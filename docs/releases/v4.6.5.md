# HOI4 Agent Tools 4.6.5

This release lets a world be written over an existing world of the same size. Before a map write the server stores review renders of the map before and after the change. They listed every building, unit and weather position, about 90 MB per render for a 5120 x 2560 world, and a replaced world changes every position, so the review passed the fixed 512 MiB in-memory ceiling (`ARTIFACT_LOGICAL_BATCH_LIMIT`) or ran the worker out of memory. The renders now count positions instead of listing them (the pictures still draw them), and the diff lists at most 2,000 changed positions per kind with the full count. Batch-limit errors now name the size reached, the limit and the largest artifacts, and a worker that stops reports the job's last progress message.

Every applied map rewrite now also returns `data.changedSummary`: how many files were changed, created, removed and modified, in total and for the 40 folders with the most changes, so a write of thousands of files no longer reads as almost unchanged when its inline file list is cut.

`hoi4.map_inspect` with `references: true` no longer reports `state = 0` (a test for a valid state, as in `NOT = { state = 0 }`) as a missing state, and reports a province id in a `prioritize` list, which takes state ids only, as `MAP_SCRIPT_PRIORITIZE_PROVINCE` instead of a missing state.

```bash
npm install --global hoi4-agent-tools@4.6.5
hoi4-agent-tools-setup --print-client-config
```

The output gains the optional `data.changedSummary` field and one diagnostic code; no tool input schema changes. See the [changelog](https://github.com/klimPaskov/hoi4-agent-tools/blob/v4.6.5/CHANGELOG.md).
