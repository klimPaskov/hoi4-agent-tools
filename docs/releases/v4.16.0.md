# HOI4 Agent Tools 4.16.0

This is a fix release for the world output record, `.hoi4-agent-world.json`. Map operations after `create_world` rewrote recorded files without recording their new hashes. This happened both in later calls and later in the `create_world` call itself. Among them were `update_states` and `move_state_provinces`. The next `create_world` then refused those files as hand edits (`MANAGED_OUTPUT_EDITED`). A ZIN world had 191 such files: 184 state files and 7 strategic regions.

Every map rewrite now records the new hash of each recorded file it writes, and drops each one it deletes, in the same transaction (`MAP_WORLD_OUTPUTS_REFRESHED`). A recorded file edited by hand before the call keeps its old hash and is named in a warning, so it stays protected.

For a mod whose record is already stale, the new `record_world_outputs` operation takes the current bytes of every recorded file as the world's own. It writes only the record, drops files that are gone, and reports the counts in `MAP_WORLD_OUTPUTS_RECORDED`:

```json
{ "operations": [{ "id": "adopt", "kind": "record_world_outputs" }] }
```

The new operation makes this a minor release. This release carries only that fix, on top of 4.15.0.

```bash
npm install --global hoi4-agent-tools@4.16.0
hoi4-agent-tools-setup --print-client-config
```

See the [changelog](https://github.com/klimPaskov/hoi4-agent-tools/blob/v4.16.0/CHANGELOG.md).
