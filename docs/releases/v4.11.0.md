# HOI4 Agent Tools 4.11.0

Every client now reads the same modding skills. `hoi4.skill` lists the skills HOI4 Mod Setup installed in the mod and loads one by name, and the same `SKILL.md` text is the resource `hoi4-agent://workspace/{workspaceId}/skill/{name}`. Both serve the kit version the mod's Setup lock pins, with the kit revision and each file's SHA-256. A file edited since Setup installed it is refused with `SKILL_TEXT_DRIFTED` unless the caller passes `acceptLocalEdits`, and a mod without a Setup lock gets its installed skills marked unpinned.

The reference tools give smaller answers. They leave out empty lists, and their search and context hits name a file under its source folder with a short id and revision instead of an absolute path and two full hashes. `reference_read` accepts the short forms and the full ones. When no mod is selected, the error names the mod folders and says what to pass. A `workspaceId` that names a mod folder matches in any letter case.

`package_check` names every missing item inline, and `package_check`, `decision_inspect` and `impact_inspect` list only the files that hold what they checked. The tool tables and example calls in `docs/tools.md` are now generated from the tool definitions and checked in CI.

Loading a skill through a live Claude Code or Codex client is not yet verified, because no mod on the test machine was set up by HOI4 Mod Setup.

A new tool and new optional output fields make this a minor release. The output schema now marks the result's list fields optional, because the reference tools omit them when they are empty. A client that requires those fields should read an absent list as an empty one.

```bash
npm install --global hoi4-agent-tools@4.11.0
hoi4-agent-tools-setup --print-client-config
```
