# HOI4 Agent Tools 4.18.0

This release fixes a game crash. The game needs every state id from 1 to the highest, and on Linux it crashes during history setup when one is missing. `merge_states` left its merged-away ids empty, and `assign_territory` left the ids of the states it dissolved: one mod had 21 such holes. A map write now moves the highest states into the holes it makes, in the same write, with their script references, building positions and `STATE_<id>` localisation, and lists the moves in `MAP_STATE_IDS_COMPACTED`. A write that would still leave a new hole, beside a state id the request names, is refused with `MAP_STATE_ID_GAP`. Holes a mod already has are reported with the `renumber_map_entity` fix, and every write still runs, so they can be closed. Building positions in `map/buildings.txt` that named a removed state now name the state that holds their province.

Also in this release:

- `hoi4.map_inspect` finds natural lands (`lands: true`), and `assign_territory` takes them as `landIds`.
- Border quality can be measured in one region (`qualityScope`).
- A focused `hoi4.event_inspect` trace that answers its question is complete, and a partial one says what is missing (ADR 0086).
- The `hoi4.mod_index` overview stays inline.
- A reply cut to the inline budget keeps the first changed files and their totals, instead of empty lists.

It is a minor version because natural lands and scoped border quality add optional inputs, and it ships the same day as 4.17.0 because it carries a crash fix. A mod written with 4.16.0 or 4.17.0 can check itself for old holes with any map write, and close each one with `renumber_map_entity`.

```bash
npm install --global hoi4-agent-tools@4.18.0
hoi4-agent-tools-setup --print-client-config
```
