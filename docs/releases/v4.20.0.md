# HOI4 Agent Tools 4.20.0

This release fixes two problems in day-to-day editing.

Map writes on maps that already have errors. On a map with many validation errors, no map write could pass: each old error blocked the write and counted against the review limit. A write can now state the map's baseline:

1. Run a full `hoi4.map_inspect` on the untouched map and take its `baselineFingerprint`.
2. Pass that value as `baselineFingerprint` to `hoi4.map_rewrite`.

The server recomputes the fingerprint and refuses the write if the map changed in between. With a match, old errors that belong to nothing the write touches stop blocking and are summed up by code. Old errors on the objects the write changes still block, and so does every new error. Without the field, a write is judged exactly as before. See [Writes over a map that already has errors](https://github.com/klimPaskov/hoi4-agent-tools/blob/v4.20.0/docs/map.md#writes-over-a-map-that-already-has-errors).

Faster inspect after a focus edit. The call that follows a rewrite now reads the index the rewrite built instead of building it again. On a small tree, the inspect after an edit that answered before its check took up to 2.4 s and now takes about 0.8 s. Durability is unchanged. An edit plus an inspect still takes 1.6 to 1.9 s, because the rewrite itself takes most of that time.

It is a minor version because `hoi4.map_rewrite` gains an optional input and `hoi4.map_inspect` gains an output field.

```bash
npm install --global hoi4-agent-tools@4.20.0
hoi4-agent-tools-setup --print-client-config
```
