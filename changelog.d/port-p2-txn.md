- The shared Rust engine now has the atomic rewrite engine (`hoi4-txn`, packet P2 of ADR 0091), with the engine operations `txn.apply` and `txn.recover`. It writes a rewrite plan whole or refuses it: paths go through the engine's one path resolver, duplicates and aliases are refused, sources are checked against the hashes their writer read under the workspace lock, and the before and after bytes are journaled in the TypeScript journal format, authenticated with the server's journal key and recorded as protected heads. Each file is replaced by rename after a write-ahead intent per batch, the written bytes are verified, and a failure restores every file without overwriting bytes the rewrite did not produce. Interrupted rewrites are recovered before the next one, and either server recovers the other's journal. The TypeScript transaction manager still serves every rewrite tool until the writers move onto the engine; nothing changes for agents yet.
