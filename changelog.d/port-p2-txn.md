- The shared Rust engine now has the atomic rewrite engine (`hoi4-txn`, packet P2 of ADR 0091). It implements the rewrite-plan applier for real writes: portable workspace-relative paths resolved through their links and kept inside the mod root and outside generated storage, duplicate and alias refusals, the workspace lock shared with the TypeScript server, stale-source checks under that lock, a journal with the before bytes and a write-ahead intent per replacement batch, atomic replacement by rename, verification of the written bytes, rollback that never overwrites bytes the rewrite did not produce, crash recovery before the next rewrite, and the structure and journal limits, each with the TypeScript refusal code. The engine operations are `txn.apply` and `txn.recover`. The TypeScript transaction manager still serves every rewrite tool until the writers move onto the engine; nothing changes for agents yet.
