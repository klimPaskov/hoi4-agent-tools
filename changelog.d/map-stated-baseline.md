- A map write can now go through on a map that already has many validation errors (issue 272, ADR 0090). Before, every error after the change that also existed before kept blocking. Each one also added a `MAP_VALIDATION_OPERATION_UNOWNED` blocker and was counted against the 100-diagnostic review limit. On a map with 3,957 existing findings and 45 new ones, every write was refused with `REWRITE_STRUCTURE_LIMIT`. A full `hoi4.map_inspect` now returns `baselineFingerprint`, a hash of the tool version and every scanned map source. `hoi4.map_rewrite` takes it back as the optional `baselineFingerprint`. The server recomputes the fingerprint on the current source and refuses the write with `MAP_BASELINE_STALE` when the map changed. With a match, both validations keep every finding up to 50,000 instead of 2,000. A pre-existing error that belongs to nothing the write touches is reported as a warning (`attributionStatus: "accepted-baseline"`) and rolled up by code. Pre-existing errors inside the write's footprint still block, and so does every new error. A stated baseline on `create_world` is refused with `MAP_BASELINE_NOT_APPLICABLE`. Without the field, a write is judged exactly as before. Tests cover the unchanged default, an accepted error, an invented and an outdated fingerprint, an error inside the footprint, a new error, and a write over 121 existing errors that passes only with a matching baseline.
