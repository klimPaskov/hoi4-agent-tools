- Report GUI keys the game refuses at load (issue 220). `hoi4.gui_inspect` with a window and scenario and `hoi4.gui_render` accepted keys that the game's GUI loader does not read, so a mod passed the offline checks with 67 refused lines in the game's `error.log` and one crash. They now report `GUI_KEY_REFUSED_BY_ENGINE` (error) for a key the installed game's own `.gui` files never write at that place (`size` on an `iconType`, `alwaystransparent` on a `containerWindowType`, `orientation` on a `scrollbarType`, a key inside a nested block), and for a block where the game only writes a value (`slider = { ... }` on a `scrollbarType`, whose `slider` names a `guiButtonType` child), and `GUI_VALUE_MALFORMED` (error) for a coordinate the game does not read in a point block (`size = { width = 18 height = 18 }` where the game reads `x` and `y`, or a bare word), each at its line, with a `gui-engine-keys` validation check. The allowed keys come from the installed game's own interface files at the same element type and block, read once per game version; without an installed game nothing is checked. On that mod's interface files the check finds the cause of each of the 67 refused lines of one launch's `error.log`. A refused key is still drawn as before; drawing an `iconType` at its sprite size follows separately.
