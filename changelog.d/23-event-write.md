- New tool `hoi4.event_write` (issue 159, first half): add, replace or remove one event block of a mod `events/*.txt` file, touching only that block. Other events, unrelated top-level blocks, comments, the namespace lines, newline style and encoding come back as they were, and the result says how many other events were checked unchanged. `add` takes the text between the braces without the id (the tool writes `id = ...` first) and a `kind` (`country_event` by default), appends the event to the file that holds its namespace, or to a new file with `file` and `createFile: true`. An id whose namespace no mod file declares is refused, with `createNamespace: true` writing `add_namespace` next to the other namespace lines. `replace` and `remove` find the event by id in the mod and keep its kind. It warns, and still writes, when a `title`, `desc` or option `name` key has no English text or the `picture` sprite is not defined. A game-only event, a duplicate id, an id in the body that differs from the call, a body that is not one balanced block and a file layout the edit cannot place safely are refused with the reason. The event chain report that #159 also asks for, and the decision writer, follow in separate changes.
