- A rewrite that waits for another rewrite's workspace lock no longer fails with `ENOENT` when that lock is released at the wrong moment. Resolving a generated path checked that it existed and then asked for its real path, and the other rewrite could remove the lock directory in between, so the waiting rewrite stopped with a raw `ENOENT: realpath ... write.lock` instead of retrying (seen in CI on `answerBeforeCheck`'s lock-wait test). A path that vanishes during that resolution is now resolved again through its nearest existing folder; a link whose target never exists still fails.
