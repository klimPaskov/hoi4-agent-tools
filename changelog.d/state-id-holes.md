- A map write no longer leaves a state id without a state (issue 182). The game needs every id from 1 to the highest and crashes at setup on a missing one; `merge_states` left the merged-away ids empty and `assign_territory` the ids of the states it dissolved (21 holes in one mod). Now the highest states move into the holes the write made, in the same write, with their script references, building positions and `STATE_<id>` localisation (the removed state's key is taken over), and the result lists the moves in `MAP_STATE_IDS_COMPACTED`. A state id the request names is never moved, and a named id that would leave holes below it is refused with `MAP_STATE_ID_GAP`. Holes the mod already had are reported as a `MAP_STATE_ID_GAP` warning with the ids and the `renumber_map_entity` fix; the write still runs, so they can be closed. On Linux the game crashes on such holes during history setup (SIGSEGV), so this is a crash fix.
