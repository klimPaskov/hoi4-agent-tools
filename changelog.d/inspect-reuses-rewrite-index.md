- The call that follows a rewrite now reads the index the rewrite just built (issue 137, maintainer decision D-98). A rewrite's after-edit check builds the workspace's new index in the job worker that ran the rewrite, but the next call took whichever warm worker was used last, and after a `hoi4.focus_rewrite` with `answerBeforeCheck: true` that worker was still busy, so the `hoi4.focus_inspect` sent right after the answer started another worker and built the index again, from nothing in a new process. A job for a workspace now goes to the worker that ran that workspace's last job when it is idle, else to another idle worker that scanned the workspace before, which rescans only the changed files. Only when no such worker is idle does it wait, at most 15 s, for the worker still finishing a rewrite; it never waits for a read. The after-edit check of a focus rewrite also fills the same reference catalog the inspect reads, so the inspect no longer builds it a second time. The reused index is still checked against the files on every call: the worker scans again, and any file changed after the rewrite is indexed again, so a stale answer is never served. The durable write is unchanged: the journal still syncs the backups, the manifest and the written files before the call answers. `scripts/bench/focus-gesture-timing.ts` times the gesture (a changed-tree rewrite, then an inspect) on the four-focus probe tree and on the benchmark mods.
