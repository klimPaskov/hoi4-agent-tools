- Add the files map operations create to the world output record (`.hoi4-agent-world.json`). `assign_territory`, `split_state`, `create_state` and the other operations created state and strategic-region files that never entered the record, so a sync that copies the recorded files left them out. ZIN's first Linux run of a redrawn map lost 124 state files this way, and the game stopped at setup. Every map rewrite now also adds each file it creates where the world keeps its outputs (state files, strategic regions, map files and world localisation, not country files), in the same transaction. `MAP_WORLD_OUTPUTS_REFRESHED` gives `added` and `addedPaths`. For mods already in this state, `record_world_outputs` now also adds the mod's files at those paths that the record lacks; `adoptUnrecorded: false` keeps the old behaviour of re-hashing listed entries only.
- `record_world_outputs` no longer drops recorded files that are on disk. Its scan did not read the bitmaps, colour maps and world scripts that only `create_world` scanned, so it dropped them as gone: on ZIN, 12 entries, among them `map/rivers.bmp`, `map/terrain.bmp` and `common/on_actions/world.txt`. A Linux copy of the recorded files then ran with the base game's rivers. It now reads every world output, and drops only recorded state and strategic-region files that are gone. Any other recorded file it did not read keeps its entry and is listed in `unscannedPaths`.
